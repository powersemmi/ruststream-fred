# Списки Redis (очередь заданий) {#redis-lists-work-queue}

Список Redis - это очередь заданий с конкурирующими потребителями: запись кладут командой `LPUSH`,
потребители снимают её справа, и достаётся она ровно одному из них.

Сервис на списках импортирует `ruststream_fred::list::prelude::*`: дескриптор и политику публикации
этой формы под именем `Publish`.

Простой режим снимает запись командой `BRPOP` и не завершает доставку: при сбое запись теряется
(at-most-once):

```rust
--8<-- "crates/ruststream-fred/examples/fred_list.rs:simple"
```

Надёжный режим переносит запись в список обработки и удаляет её, когда обработчик подтверждает,
поэтому при сбое задание повторяется, а не теряется (at-least-once):

```rust
--8<-- "crates/ruststream-fred/examples/fred_list.rs:reliable"
```

Запись надёжного режима, которую обработчик отверг, возвращается в основной список, если nack просит
вернуть её в очередь, и оттуда её берёт любой потребитель. Nack без возврата в очередь отбрасывает
запись, и задание больше не выполняется.

Политика `RedisListPublish` публикует командой `LPUSH`. Вы указываете её в точке монтирования
обработчика, и рантайм инстанцирует по ней издателя на подключённом брокере; вне приложения издателя
отдаёт напрямую `connected.list_publisher(RedisListPublish::new())`.

Запись списка упакована так же, как сообщение [Pub/Sub](pubsub.md): двоичный кадр, в котором
проходят любые байты, или конверт, сериализованный кодеком, когда один и тот же кодек задан с обеих
сторон (`.codec(JsonCodec)`).

Снятие возвращает одну запись, поэтому пакеты подписчик собирает сам. Пакетный обработчик называет
свой размер через `batch(n)` в точке монтирования и никогда не видит пакета длиннее; `block(..)` идёт
по цепочке после размера, как и на потоке (см. [Пакеты](streams.md#batches)).

## Восстановление осиротевших записей {#orphan-recovery}

Потребитель, умерший посреди обработчика, оставляет свою запись в списке обработки: списки Redis не
отмечают ничего как неподтверждённое. Указание ключа ZSET включает сторожевой механизм
восстановления, по умолчанию выключенный:

```rust
--8<-- "crates/ruststream-fred/examples/fred_list.rs:recovery"
```

Подписка записывает каждый захват в ZSET под временем захвата и просматривает ZSET по ходу чтения.
Запись, простоявшая дольше `min_idle`, возвращается в основной список, и там её снова берёт живой
потребитель. Задайте `min_idle` больше самого долгого времени работы обработчика: меньшее значение
восстанавливает запись, которую ещё обрабатывают, и задание выполняется дважды. `recovery_ttl`
убирает брошенный ключ ZSET по истечении срока и должен быть больше `min_idle`. Если нужна
долговечная очередь, которая восстанавливается сама, возьмите Redis Streams.

## TTL издателя списка {#list-publisher-ttl}

TTL на ключе списка ограничивает простаивающую очередь:
`RedisListPublish::new().ttl(Duration::from_secs(300))` заново выставляет `PEXPIRE` при каждой
публикации, поэтому очередь в работе не истекает никогда, а простаивающая пропадает. По умолчанию
TTL выключен и покрывает весь список: у отдельных записей списка Redis срока жизни нет.
