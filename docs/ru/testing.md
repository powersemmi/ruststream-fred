# Тестирование {#testing}

Фича `testing` поставляет `RedisTestBroker` - внутрипроцессный транспорт, который маршрутизирует по
точному ключу потока, без сервера. Он воспроизводит маршрутизацию, подтверждение и заголовки. Он не
воспроизводит курсоры групп потребителей, повторную доставку через `XAUTOCLAIM`, обрезку и
маршрутизацию в dead-letter, поэтому им место в тесте против настоящего сервера.

```toml
[dev-dependencies]
ruststream-fred = { version = "0.7", features = ["testing"] }
```

## Юнит-тестирование обработчика {#unit-testing-a-handler}

Обработчик `#[subscriber]` работает внутри приложения `RustStream`, поэтому тест собирает такое же
приложение вокруг `RedisTestBroker` и отдаёт его `TestApp`. Публикация через дескриптор обвязки
доводит реакцию до полной остановки, поэтому проверкам после неё ждать не нужно.

### Тест бизнес-логики {#business-logic-test}

Обработчик проверяет свой вход, сохраняет корректное через коннектор репозитория, а остальное
отбрасывает. Ничто в нём не знает о тестовой обвязке.

```rust
--8<-- "crates/ruststream-fred/examples/fred_testing.rs:repository"
```

```rust
--8<-- "crates/ruststream-fred/examples/fred_testing.rs:business-handler"
```

Тест публикует корректный платёж и некорректный, а потом проверяет, что сохранён только корректный:

```rust
--8<-- "crates/ruststream-fred/examples/fred_testing.rs:business-test"
```

В вашем крейте то же тело кладут в `#[tokio::test]` внутри модуля `#[cfg(test)]`:

```rust
--8<-- "crates/ruststream-fred/examples/fred_testing.rs:unit-test"
```

## Что тестовый брокер монтирует, что игнорирует и что отвергает {#what-the-stand-in-mounts-ignores-and-refuses}

Любой дескриптор и любая политика публикации из этого крейта монтируются на `RedisTestBroker`,
поэтому тест собирает то же объявление, которое поставляет сервис. Три обработчика выше написаны с
`RedisStream`, `RedisList` и `RedisPubSub` ровно так, как их пишет файл маршрутов: без голой
строки-ключа и без подмены в точке монтирования. Сторона ответа - то же значение, что и в боевом
коде:

```rust
--8<-- "crates/ruststream-fred/examples/fred_testing.rs:reply-handler"
```

```rust
--8<-- "crates/ruststream-fred/examples/fred_testing.rs:reply-test"
```

`Publish` из прелюдии каждой формы инстанцирует издателя на подключённом тестовом брокере так же, как
на настоящем, и он же служит тестовому брокеру издателем ответов по умолчанию, поэтому обработчик,
который отвечает, не называя политику, работает и здесь. Отдельной политики публикации для тестов
нет.

Тестовый брокер маршрутизирует по ключу или каналу и больше ни по чему. Имена потребителя и группы,
`start_id`, `block`, `dead_letter`, `max_deliveries`, `delayed_retry`, список обработки режима
`reliable` вместе со сторожевым механизмом восстановления, режим `mode` у Pub/Sub и кодек конверта
`codec` в процессе не меняют ничего. На стороне публикации так же: у `ttl` списка нет ключа, который
мог бы истечь, а кодек конверта не выполняется, поэтому ответ читается здесь голой полезной нагрузкой,
а на настоящем сервере - кадром. Всё это проверяйте против настоящего сервера.

Совместимости совпадают по формам. Политика потока конструирует издателя с обеими разновидностями
транзакций, как и `RedisPublisher`; политики списка и Pub/Sub конструируют `RedisTestPlainPublisher`,
который даёт только `Publisher`, как `RedisListPublisher` и `RedisPubSubPublisher`. Слот с
ограничением на транзакционную совместимость не компилируется в процессе ровно там, где он не
компилируется против настоящего сервера, а не проходит под обвязкой, чтобы сломаться на боевой
сборке.

Две ошибки конфигурации здесь ловятся так же, как их ловит Redis: поток без группы потребителей и
ZSET восстановления для списка без `min_idle`. Два дескриптора отвергаются сразу, потому что их
исполнение в процессе выдало бы то, чего настоящая подписка не выдаёт никогда:

- `RedisStream::reclaim(..)` читает застоявшиеся неподтверждённые записи другого потребителя.
  Тестовый брокер списка неподтверждённых не ведёт, поэтому такое монтирование отдало бы обработчику
  свежие записи.
- `RedisPubSub::pattern()` подписывается по шаблону. Тестовый брокер сравнивает имена каналов точно,
  поэтому такое монтирование молчало бы на каждом канале, который шаблон должен ловить.

Доставка завершается по правилам транспорта. Поток и надёжный список подтверждают, а возврат в
очередь доставляет заново; Pub/Sub и простой список возвращают `AckError::Unsupported` и отказывают в
возврате в очередь - здесь ровно так же, как на настоящем сервере. Дескриптор, переживший
`shutdown`, возвращает `RedisError::ShutDown`, а не пишет в роутер, которого никто не читает.

## Против настоящего сервера {#against-a-real-server}

Собственный живой набор тестов крейта лежит в `tests/integration_fred.rs` и покрывает то, чего
внутрипроцессный транспорт не может: настоящие группы потребителей, `XACK`, путь повторной публикации
по nack, перехват через `XAUTOCLAIM`, а также топологии кластера и sentinel. Каждая топология
закрыта своей переменной окружения, поэтому `cargo test` без единой заданной переменной обходится без
сервера. `docker-compose.test.yml` поднимает все три, а `just test-brokers` запускает их и прогоняет
набор.
