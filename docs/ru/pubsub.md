# Pub/Sub {#pubsub}

Pub/Sub работает без подтверждений: сообщение доходит до подписчиков, подключённых в этот момент, а
`ack` и `nack` возвращают `Unsupported`.

Сервис на Pub/Sub импортирует `ruststream_fred::pubsub::prelude::*`: дескриптор, его режим и
политику публикации этой формы под именем `Publish`.

Дескриптор `RedisPubSub` называет канал и режим. Классическая доставка доходит до каждого узла
кластера, а `.pattern()` подписывает на шаблон каналов вместо одного канала:

```rust
--8<-- "crates/ruststream-fred/examples/fred_pubsub.rs:classic"
```

Шардированная доставка (`SSUBSCRIBE`, Redis 7+) остаётся в пределах слота, поэтому масштабируется по
кластеру и шаблонов не принимает: дескриптор, который просит и то и другое, отвергается при
монтировании подписки. `.mode(PubSubMode::Sharded)` выбирает её для отдельной подписки:

```rust
--8<-- "crates/ruststream-fred/examples/fred_pubsub.rs:sharded"
```

Один сервис одновременно держит классический Pub/Sub на отдельном сервере и шардированный на
кластере; каждый обработчик монтируется на своём брокере:

```rust
--8<-- "crates/ruststream-fred/examples/fred_pubsub.rs:app"
```

Политику этой формы вы указываете в точке монтирования обработчика: `.out_reply(Publish)`, а
`.mode(PubSubMode::Sharded)` приводит её в соответствие с шардированным подписчиком. Позиция, к
которой она привязана, - это значение, которое возвращает обработчик. Такая политика отправляет
ответ командой `PUBLISH`, а не командой `XADD` издателя брокера по умолчанию.

Канал ответа задаёт тип ответа: `AuditEntry` выше объявляет `audit`. Тип ответа, который канала не
объявляет, уходит туда, куда указывает `publish("..")` подписчика.

Pub/Sub доставляет по одному сообщению за раз, поэтому пакеты подписчик собирает сам. Пакетный
обработчик называет свой размер через `batch(n)` в точке монтирования и никогда не видит пакета
длиннее (см. [Пакеты](streams.md#batches)).

Публикация упаковывает заголовки вместе с полезной нагрузкой. Кадр по умолчанию двоичный. Один и тот
же кодек на подписчике и на издателе (`.codec(JsonCodec)`) переключает её на конверт
`{headers, payload}`, который сериализует кодек: значение становится читаемым в инструментах вроде
RedisInsight. В обоих кадрах любые байты проходят без изменений: в конверте поле с корректным UTF-8
записывается текстом, а любые другие байты - как есть. Значение, опубликованное внешним клиентом,
приходит как полезная нагрузка без заголовков.
