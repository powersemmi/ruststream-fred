# Устройство

Где стоит `ruststream-fred`: между рантаймом RustStream и клиентом fred, собственный клиент на
каждую подписку, один общий пул.

<Diagram name="design" words={words} />

Крейт реализует трейты брокера из ядра поверх [fred](https://docs.rs/fred/10.1.0/fred/). Рантайм
над ним один для всех брокеров. Всё, что относится к Redis, находится в этом крейте: дескрипторы
трёх транспортов, смысл подтверждения в каждом из них, адрес копии для переобработки и окно
конвейера.

Дескриптор разрешается один раз, при запуске, по подключённому брокеру и даёт подписчика.
Подписчик - поток доставок, который рантайм опрашивает. Рантайм декодирует каждую доставку,
вызывает обработчик и завершает доставку с его исходом. Политика публикации конструирует издателя
и при запуске инстанцирует его на подключённом брокере.

Каждая подписка читает через собственный клиент, поэтому заблокированное чтение никогда не
задерживает публикацию. Публикации, завершения доставок и команды обработчика делят общий пул.
Когда открывается и закрывается каждый клиент, показывает страница
[Жизненный цикл](lifecycle.md), а путь одной записи - страница [Путь](path.md).

Запись потока хранит полезную нагрузку в поле `_payload`, а каждый заголовок - в поле
`h:<name>`, поэтому `XADD` и `XREADGROUP` сохраняют и то и другое. Запись списка и сообщение
канала хранят заголовки в обёртке вокруг полезной нагрузки: в двоичном кадре или в конверте
кодека, если дескриптор указывает кодек.
