# Рассылка

Redis Pub/Sub передаёт сообщение подпискам, подключённым в момент публикации, и ничего не хранит
для остальных.

<Diagram name="broadcast" words={words} />

Канал - это имя, а не ключ: Redis ничего под ним не хранит. `PUBLISH` передаёт сообщение каждому
клиенту, подписанному на канал в этот момент. Redis называет такую доставку at-most-once: клиент,
который не подписан или потерял соединение, сообщение не получит
([Pub/Sub](https://redis.io/docs/latest/develop/pubsub/)).

Каждая подписка [`RedisPubSub`](api:ruststream_fred::pubsub::RedisPubSub) открывает собственный
клиент и подписывает его на канал. Классическая подписка готова, когда сервер ответил на `PING`,
отправленный по тому же соединению, поэтому сообщение, опубликованное после подписки, до неё
доходит. [`RedisPubSubPattern`](api:ruststream_fred::pubsub::RedisPubSubPattern) подписывается
на шаблон в стиле glob командой `PSUBSCRIBE` и получает сообщения каждого подходящего канала.

Сообщение ждёт в буфере клиента, пока обработчик его не заберёт. Буфер вмещает 32 сообщения,
значение `fred` по умолчанию, если [`buffer`](api:ruststream_fred::pubsub::RedisPubSub::buffer)
не задаёт другой размер. Отстающая подписка теряет самые старые сообщения и пишет в журнал
предупреждение с именем канала и числом потерянных сообщений.

Классический Pub/Sub рассылает каждое сообщение на все узлы кластера. Шардированный Pub/Sub
(`SSUBSCRIBE` и `SPUBLISH`, начиная с Redis 7.0) закрепляет канал за хеш-слотом и держит его
сообщения внутри этого шарда. [`PubSubMode`](api:ruststream_fred::pubsub::PubSubMode) выбирает
один из режимов, и подписка в одном режиме не получает того, что опубликовано в другом.

Доставке Pub/Sub нечего завершать: `ack` и `nack` возвращают `AckError::Unsupported`.
